# Vocaband performance and quality audit

Baseline: `5d8bef00`. This is a scoped code audit, not a claim that every game,
device, production service, or user journey has been validated.

## Keep the experiences separate

| Experience | Relevant boundary | Scope of this patch |
| --- | --- | --- |
| Student assignment play | `useAppController`, `assignmentWords`, active assignment | English audio warming only while a student is in the game view |
| Teacher workspace / previews | Teacher views and setup flows | No gameplay or navigation changes; student prefetch explicitly disabled |
| Public demo | `PublicViews` → `DemoModeWrapper` → standalone `DemoMode` | No changes to demo vocabulary, scores, or game logic |
| Live games / Quick Play | Separate host/student views and socket protocols | No protocol, scoring, or session lifecycle changes |
| Developer administration | `views/developer/ConfirmDialog` | Accessible dialog semantics, keyboard focus, larger close target, mobile overflow |
| Hebrew subject | Separate corpus/audio namespace | English assignment prefetch explicitly disabled |

## Confirmed fixes

1. **Uncancelled audio prefetch:** the old effect never cancelled its idle timer
   or network work. Its ref suppressed reruns before work actually completed.
   The replacement depends on sorted unique finite IDs, cancels timers and
   requests, survives StrictMode, checks the network before each batch, and
   waits for response bodies before starting the next batch. The controller
   now disables it outside student English assignment gameplay.
2. **Admin confirmation accessibility:** dialog role/name/description and input
   labels were missing, focus could leave the modal, and tall content could
   overflow small viewports. The dialog now traps/restores keyboard focus,
   exposes labels and busy state, disables editing while busy, scrolls within
   the viewport, and has a 44px close target. Existing destructive-action
   phrase/reason checks remain intact.
3. **Lint startup failure:** the installed TypeScript 7 package lacks the API
   expected by typescript-eslint. Use Microsoft's documented side-by-side
   aliases: TypeScript 6 API for tools and TypeScript 7 `tsc` for typechecking.
   See [Microsoft migration guidance](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/#running-side-by-side-with-typescript-6.0).

## Validation

- Existing suite: 533 tests passed. With seven new regression tests: 540 passed
  across 54 files. Focused audio/dialog suite: 13 passed.
- Full TypeScript check passed.
- Lint now completes: zero errors, 264 existing warnings. Warning cleanup is
  separate work; rules were not weakened or disabled.
- Production Vite build passed. This environment blocks the `tsx` CLI IPC pipe,
  so the two prebuild generators were run with `node --import tsx`, followed by
  the Vite CLI directly; application build configuration was not changed.
- Entry closure: 75.0 kB gzip across four chunks, within the existing 80 kB gate.
  This is a bundle-size measurement, not a real-device loading-speed score.
- npm audit returned zero reported dependency vulnerabilities; this does not
  establish application authorization or database security.
- Public landing, demo welcome and demo teacher-preview screens were inspected
  in the live desktop browser. Authenticated dashboards, mobile screenshots,
  changed admin modal screenshots and real multiplayer sessions remain
  unverified. The modal changes have DOM/keyboard regression coverage.

## Design review — observations and proposals

These are proposals, not a wholesale redesign or changes to game rules.

| Surface / evidence | Keep | Proposed improvement |
| --- | --- | --- |
| Public landing, live desktop inspection | Separate teacher and student cards; obvious class-code action | Reduce glow and competing gradients; increase secondary-copy contrast; simplify the dense top navigation; make the demo button easier to notice |
| Demo welcome, live inspection | Persistent DEMO label, language choice, separate teacher preview | Stronger secondary teacher-preview button; less decorative header height; explain that the default demo starts with the student experience |
| Demo teacher preview, live inspection | Clear mastery bars, readable light report cards | Put “sample data” beside the heading, not only in the bottom disclaimer; avoid a LIVE badge implying that the static sample is a real session |
| Real English teacher dashboard, code review only | Existing StartHerePanel; live games separated from management | Consider one column on narrow phones (currently two at all small widths); reduce decorative motion around operational controls; prioritize class/task actions in the teacher's chosen workflow |
| Real student dashboard, code review only | Pet and orbital identity; task count badge | Offer a direct Continue assignment action in addition to the Tasks sheet, so a child can start assigned work without discovering the orbit first |
| Student mode selection, code review only | Recommended next island, difficulty sheet, reduced-motion support | Validate legibility of map labels at 320–360px and in Arabic; retain teacher-allowed mode filtering and each game's distinct instructions |

Live-page content also needs a consistency pass: the hero advertises 15 modes
while the FAQ says 11, and the FAQ still describes individual teacher use as
completely free. Verify actual commercial policy before changing pricing copy.
The landing DOM exposes a lengthy visually hidden block of spelling variants
and keywords to the accessibility tree; review whether this belongs in a
screen-reader user's reading path. These are observed content issues, not
claims that any particular search ranking or compliance requirement is met.

## Prioritized follow-up

1. **Dashboard consistency:** inspect `useDashboardPolling` with mocked delayed
   requests. Student class lookup occurs twice during initialization and can
   finish after cleanup; its callbacks lack a disposed guard. Teacher channels
   share one fallback timer, so one healthy channel can clear another's fallback;
   classes beyond the five-channel cap have no dedicated polling setup. Test
   these independently from login/authentication and game score saving.
2. **Role-specific UX checks:** teacher create → assign → monitor; student
   join → select mode → play → results → dashboard; demo enter → play → exit.
   Run each separately in EN/HE/AR and small mobile viewports. For every live
   game, separately verify host start/end and student reconnect/removal.
3. **Actual classroom performance:** capture cold/warm traces on a low-end phone
   and throttled Wi-Fi. Preserve the existing entry budget. Large export chunks
   include ExcelJS (~256 kB gzip) and html2pdf (~219 kB gzip); verify their request
   timing before deciding whether more splitting helps.
4. **Incremental maintainability:** `server.ts` has 8,563 lines,
   `FreeResourcesView.tsx` 3,656, and `DemoMode.tsx` 2,895. Extract one tested
   responsibility at a time. Do not merge demo and student state just because
   their UI looks similar, or combine host and participant lifecycles.

The repository's `CLAUDE.md` explicitly protects auth, backend/proxy, database,
shared core contracts and CI. None of those protected files are modified here.
